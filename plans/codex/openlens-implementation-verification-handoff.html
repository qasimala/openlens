2. Outcome and intended user workflow

  1. One-time setup: install the Android app, grant Android camera permission, authorize the computer for USB debugging, install OpenLens Desktop/OBS integration, and prepare /dev/video42.
  2. Connect the S24 Ultra with a USB data cable and leave it unlocked.
  3. Open OpenLens from the Linux application menu.
  4. Choose quality and camera settings, then click Start camera on the PC.
  5. The desktop creates a random per-session socket name, forwards it over ADB, launches the Android activity, and the phone starts the foreground camera service automatically. There is no per-session phone confirmation button.
  6. Use the OpenLens V4L2 device or native OpenLens source in OBS.
  7. Click Stop camera on the PC to release Camera2, MediaCodec, the local socket, ADB forward, decoder, and virtual camera. The phone notification also retains an emergency Stop action.
Boundary: the secure phone lock screen is not bypassed. The current product requires the phone to be unlocked when starting a new session. Android’s one-time camera permission and one-time USB-debugging authorization are still required.

3. Architecture

S24 Camera2
Camera frames and controls
MediaCodec
Hardware H.264 encoder
ADB USB socket
Random abstract socket → loopback forward
Desktop core
Protocol parser + FFmpeg decoder
OBS output
V4L2 /dev/video42 or native source

Control flow

The desktop is the session owner. It discovers the ADB device, checks app installation, creates the forward, launches the Android activity with the random session and preset, connects, performs HELLO/CAPABILITIES/CONFIGURE, sends camera controls, receives video/config/stat/error messages, and sends END_STREAM during orderly shutdown.

Transport properties

  • No LAN transport and no Android network permission.
  • ADB forwards a random Android abstract socket only to host loopback.
  • Binary framed protocol has Kotlin and C++ implementations plus shared valid/malformed fixtures.
  • Video payload is H.264; desktop output is decoded I420 suitable for OBS/V4L2.

5. Important fixes and product decisions

5.1 Product naming

Earlier development naming using phonecam was replaced with OpenLens across binaries, UI, package IDs where applicable, desktop entry, icon, OBS integration, documentation and developer bundle. The packaging script explicitly removes an obsolete phonecam artifact if present.

5.2 Stale Android socket/session replacement

A foreground service could remain blocked on LocalServerSocket.accept() for an old random session while the desktop forwarded a new random session. This made the UI appear stuck.

  • CameraStreamingService now tracks activeSession and pendingSession under sessionLock.
  • A new request closes the active client, wakes the old abstract socket with a temporary LocalSocket, closes the old server, and chains into the replacement session.
  • MainActivity compares its requested session with the active service session so stale service state cannot show an incorrect Stop-only UI.

5.3 Phone approval UI and later PC-controlled auto-start

The first UI fix moved a full-width Start button above the preview so it was visible in landscape. The subsequent product decision removed per-session phone approval entirely:

  • A Compose LaunchedEffect(sessionName, permissionGranted) waits for the preview surface, then calls startSession() automatically for a new desktop request.
  • The manual Start button and its callback were removed from the session screen.
  • The desktop now says the camera is starting automatically rather than asking for phone approval.
  • One-time Android camera permission and USB-debugging authorization remain.

5.4 Rotation stopping the stream

Rotating from landscape to portrait recreated the activity and destroyed the TextureView surface used by the active Camera2 capture session. The activity now handles keyboardHidden|orientation|screenLayout|screenSize|smallestScreenSize configuration changes itself. Compose relayouts without destroying the activity/camera surface.

5.5 Secure lock-screen boundary

An experiment to show the activity above the lock screen was not retained or installed. The final source and installed APK do not declare showWhenLocked. New sessions require an unlocked phone, while no per-session tap is required once unlocked.

6. Security and privacy behavior

Trust model: an ADB-authorized computer is highly trusted and may start an OpenLens camera session while the phone is unlocked. This is now intentional product behavior. The camera is never silently hidden: Android’s privacy indicator and foreground notification remain active.

9.3 Physical automatic-start test

  1. Install the newly rebuilt APK, not the bundled APK, on the reference S24.
  2. Unlock the phone and leave it on the launcher. Do not open or tap OpenLens.
  3. Start a short stream from OpenLens Desktop.
  4. Verify the OpenLens activity appears and streaming begins without a phone tap.
  5. Verify Android’s camera privacy indicator and foreground notification are visible.
  6. Verify desktop preview/frame count and OBS video both advance.
  7. Stop from the PC and confirm the Android service, camera indicator and ADB forward disappear.
  8. Lock the phone and confirm a new session does not bypass the secure lock screen.

9.4 Rotation regression

  1. Start a 60-second stream and record frame/sequence counters.
  2. Rotate portrait → landscape → portrait at least ten times.
  3. Confirm the desktop session never exits, Camera2 does not report a surface error, the preview relayouts, frame counters continue, and OBS does not freeze.
  4. Retain logs/statistics and update the release evidence only if results are reproducible.

9.5 Stale-session regression

  1. Create an old waiting Android session and remove its desktop forward without stopping the phone service.
  2. Start a new desktop session with a different random name.
  3. Confirm the service replaces the old listener, the new socket accepts, and real frames arrive.
  4. Confirm no old @openlens_… socket remains after shutdown.

9.6 OBS test

  1. Verify /dev/video42 exists and accepts I420 at the selected resolution/fps.
  2. Add Video Capture Device (V4L2) and select OpenLens//dev/video42.
  3. Separately install and test the native OpenLens Phone Camera source.
  4. Confirm stopping/hiding behavior, reconnect slate, frame color range and timestamps.

12. Recommended acceptance checklist

  1. Source builds from a clean checkout with documented dependencies.
  2. Android lint and Kotlin camera/protocol unit tests pass.
  3. C++ core/protocol/GUI smoke tests pass; OBS skip reason is understood.
  4. All developer bundle checksums verify and SPDX JSON parses.
  5. PC Start triggers the unlocked S24 without any phone tap.
  6. PC Stop releases camera, service, socket, forward and V4L2 ownership.
  7. Locked phone is not bypassed.
  8. Android camera privacy indicator and notification are visible throughout capture.
  9. Portrait/landscape changes do not end or freeze a session.
  10. A stale old session is replaced by a new desktop request.
  11. OBS receives stable video through V4L2 and the native source.
  12. No runtime phonecam branding remains.
  13. Reviewer explicitly lists every remaining release blocker.
